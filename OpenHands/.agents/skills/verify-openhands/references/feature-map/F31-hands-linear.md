# F31 — Bossku Hands Linear inbox and team settings

Bossku Hands can start a coding session from a Linear issue. The **Linear inbox** lists the open issues assigned to you (`/hands/linear`). Each issue has a **Start session** button when its Linear team is mapped to a local repository; a team that is not mapped shows a reason and a link to set it up. An issue that already has a session links to it instead. **Linear teams** under Settings (`/settings/hands-linear`) maps each Linear team to a repository folder, a base branch and the Done state that a completed session moves the issue to; saving replaces the whole map. The inbox and team list read from the local Hands service at `/api/hands/linear/*`, which reads its API key from the environment, never from this page.

Source: `src/routes/hands-linear.tsx`, `src/routes/hands-settings-linear.tsx`, `src/components/features/hands/linear/`, `src/components/features/hands/settings/hands-linear-form.tsx`, `src/components/features/hands/hands-section-nav.tsx`, `src/components/features/hands/hands-labels.ts`, `src/constants/settings-nav.tsx`.

## Sub-features

- `F31.entry-points`: the **Linear** tab in the Hands section nav (`/hands/linear`), the command menu entries **Linear** and **Linear teams**, the Settings navigation entry **Linear teams** (`/settings/hands-linear`), and the **Set up team** link on an unmapped issue all lead here; the direct URLs `/hands/linear` and `/settings/hands-linear` work too.
- `F31.inbox-list`: `/hands/linear` shows `hands-linear-list` (one `hands-linear-issue-<IDENTIFIER>` per issue) with the identifier, title, and a line of team key, state, priority and "updated" time, plus **Open in Linear**, a link that opens in a new tab.
- `F31.inbox-empty`: with no open issues assigned to you, `hands-linear-empty` says "No open issues are assigned to you."
- `F31.inbox-error`: when the issues cannot load and nothing is cached, `hands-linear-error` (role `alert`) shows a message for the code and a **Retry** button. Codes: `linear_key_missing` names `BOSSKU_HANDS_LINEAR_API_KEY` or `LINEAR_API_KEY`; `linear_key_invalid` says Linear rejected the key; `linear_rate_limited` asks to wait a minute; `linear_request_failed` says Linear could not be reached.
- `F31.start`: an issue with no session and a mapped team has an enabled **Start session** button. Clicking it shows "Starting..." while pending, then a `role="status"` line "Session started." with an **Open session** link to `/hands/sessions/<id>`. The page does not navigate by itself.
- `F31.start-unmapped`: an issue whose team has no mapped repository has a disabled **Start session** button, the text "Set up the <TEAM> team in Linear settings before you start a session." and a **Set up team** link to `/settings/hands-linear`.
- `F31.start-conflict`: an issue that already has a running session shows **Open session** in place of Start. If a start is refused with `linear_issue_in_progress`, `role="alert"` shows the reason and an **Open session** link to that session.
- `F31.settings-list`: `/settings/hands-linear` shows `hands-linear-form` with one section per team (`hands-linear-team-<KEY>`) for every saved team and every team seen in the inbox. Each has a Repository folder field, a Base branch field and a Done state select. With no teams it says "No teams yet. Add a team by its key, or open the Linear inbox to load your teams."
- `F31.settings-done-state`: the Done state select (`hands-linear-done-<KEY>`) is disabled with "Open the Linear inbox once to load this team's Done states." until the team's id is known from an inbox issue. Once loaded it lists the team's states with **First completed state** as the default (no value). A saved state that is no longer listed still shows as its raw id. A failed load shows "Could not load this team's states." (`role="alert"`).
- `F31.settings-add-remove`: **Add team** (or Enter in the key field, `role="group"`) adds a row by its Linear team key. A key that does not match letters, numbers, `-` or `_` (up to 16 characters) shows "Use letters, numbers, - or _, up to 16 characters."; a key already listed shows "That team is already in the list.". **Remove team** drops the row only; nothing is saved until **Save settings**.
- `F31.settings-save`: **Save settings** (`hands-linear-save`) sends the whole team map. Success shows `hands-linear-saved`; a refused save shows `hands-linear-error`. After a reload the saved values are back, and a removed team is gone. Empty repository and base branch fields are stored as no value.
- `F31.settings-load-error`: when the Hands settings cannot load, `hands-linear-settings-load-error` shows its load-error copy with a **Retry** button.

## How to get to it (user POV)

- The **Linear** tab in the Hands section nav, reached from **Sessions** (`sidebar-hands-sessions-link`) or **Reviews**.
- The command menu: **Linear** (inbox) or **Linear teams** (settings).
- Settings navigation **Linear teams**.
- **Set up team** on an unmapped issue in the inbox.
- Direct URLs `/hands/linear` and `/settings/hands-linear`.

## Driving it with control-openhands

Preconditions:

- Baseline state (launched, doctored, `onboard --skip` done). The Hands service must be running; check `control-openhands api GET /api/hands/linear/issues` first.
- A real inbox needs a Linear key in the environment of the Hands service (`BOSSKU_HANDS_LINEAR_API_KEY` or `LINEAR_API_KEY`), set before the service starts. Never type the key into a page or paste it in a command line that is recorded. Without it the inbox shows `F31.inbox-error` and the team list is empty: that is the expected result for a keyless run, not a pass of the other rows.
- A fixture repo for a real start: `control-openhands fixture git-repo --name qa-hands-repo`. Map the team to it first (settings below). Task text starts with `QA_`.
- Desktop viewport unless a bullet says otherwise.

- **Entry points (`F31.entry-points`).** From `/`, `control-openhands browser click 'testid=sidebar-hands-sessions-link' --expect-url '/hands/sessions(\?|$)'`, then `control-openhands browser click 'role=navigation >> role=link[name="Linear"][exact]' --expect-url '/hands/linear(\?|$)'`. Record UI entry for that check. Then `control-openhands browser goto /settings/hands-linear` for the direct URL.
- **Inbox list (`F31.inbox-list`).** On `/hands/linear`, `control-openhands browser count '[data-testid^="hands-linear-issue-"]'` equals the number of entries in the array that `control-openhands api GET /api/hands/linear/issues` returns. `control-openhands browser snapshot 'testid=hands-linear-list'` shows identifiers and titles. `control-openhands browser screenshot --feature F31.inbox-list --name inbox`.
- **Inbox empty and error (`F31.inbox-empty`, `F31.inbox-error`).** With an empty assignment list, `control-openhands browser text 'testid=hands-linear-empty'`. With no key, `control-openhands browser text 'testid=hands-linear-error'` names `BOSSKU_HANDS_LINEAR_API_KEY` or `LINEAR_API_KEY`. Click **Retry** in that panel and check it again. Rate limits and bad keys are not forced in a normal run: record them `blocked` unless the service was started with a bad key by this run.
- **Start (`F31.start`).** On a mapped team's issue (`testid=hands-linear-issue-<IDENTIFIER>`), `control-openhands browser click 'testid=hands-linear-issue-<IDENTIFIER> >> role=button[name="Start session"]'`, then `control-openhands browser wait 'testid=hands-linear-issue-<IDENTIFIER> >> role=status' --timeout 30000`. The status says "Session started." and `control-openhands browser click 'testid=hands-linear-issue-<IDENTIFIER> >> role=link[name="Open session"]' --expect-url '/hands/sessions/[^/]+'` opens the session. Confirm on the session page (`F30.detail`) and `control-openhands api GET /api/hands/sessions` finds one session whose `linear.identifier` matches. Blocked when no key is set.
- **Unmapped team (`F31.start-unmapped`).** On an issue whose team is not in the map, `control-openhands browser count 'testid=hands-linear-issue-<IDENTIFIER> >> role=button[name="Start session"][disabled]'` is `1`, and `control-openhands browser text 'testid=hands-linear-issue-<IDENTIFIER>'` contains the set-up sentence. Click **Set up team** with `--expect-url '/settings/hands-linear'`.
- **Conflict (`F31.start-conflict`).** Click Start again on the same issue after it has a session: the button is replaced by **Open session**, and the count of Start buttons is `0`. A stale page (a second tab, or Start pressed before the first call finished) shows `testid=hands-linear-issue-<IDENTIFIER> >> role=alert` with the in-progress reason and an **Open session** link. Read `api GET /api/hands/sessions` to confirm only one session exists.
- **Settings list (`F31.settings-list`).** `control-openhands browser goto /settings/hands-linear`, then `control-openhands browser count '[data-testid^="hands-linear-team-"]'`. Each section shows Repository folder, Base branch and Done state. With no teams `control-openhands browser text 'testid=hands-linear-form'` contains "No teams yet."
- **Done state (`F31.settings-done-state`).** A team that has an inbox issue shows an enabled `testid=hands-linear-done-<KEY>`; a team with no loaded issue shows the disabled select with the "Open the Linear inbox once" hint. Open the select and pick a state, then save (below) and reload: `control-openhands api GET /api/hands/settings --pick linear.teams.<KEY>.doneStateId` returns the chosen id.
- **Add and remove (`F31.settings-add-remove`).** `control-openhands browser fill 'testid=hands-linear-form >> role=group >> role=textbox' QA_BAD!`, click **Add team**: `control-openhands browser text 'role=alert'` says "Use letters, numbers, - or _, up to 16 characters." Fill `QA-TEAM` instead and press Enter in the field: a new `hands-linear-team-QA-TEAM` section appears but nothing is saved yet (`control-openhands api GET /api/hands/settings` unchanged). Click **Remove team** on that section: it disappears. Adding a key already listed shows "That team is already in the list.".
- **Save and read back (`F31.settings-save`).** Set a repository folder on a real team (use the `qa-hands-repo` path from the fixture) and a base branch `main`, click `testid=hands-linear-save`, `control-openhands browser wait 'testid=hands-linear-saved' --timeout 10000`, then `control-openhands browser reload` and `control-openhands api GET /api/hands/settings --pick linear.teams`. The values match and a removed team is absent. Restore the original values afterwards. If the service refuses the save, `testid=hands-linear-error` shows the message and nothing new is stored.
- **Settings load error (`F31.settings-load-error`).** Only on a run that stopped the Hands service: `control-openhands browser goto /settings/hands-linear` shows `testid=hands-linear-settings-load-error` with **Retry**. Restart the service afterwards. If the service is not under this run's control, record `blocked`.
- **Phone (`F31.inbox-list`).** `control-openhands browser viewport phone`, then `control-openhands browser bbox 'testid=hands-linear-list'` and check `pageHorizontalOverflow` is `false` on `/hands/linear` and `/settings/hands-linear`. Return with `control-openhands browser viewport desktop`.

## Gotchas

- Without a Linear key the inbox and the team list are empty or in error by design. Check `GET /api/hands/connections` (`linear.error`) to tell "no key" from "no issues".
- Mock mode (`src/mocks/hands-handlers.ts`) serves fixture issues (`ENG-101`, `ENG-102`, `OPS-7`) and the start call, but never reaches Linear and never opens a real repo; start-to-session rows are `blocked` there unless the session is genuinely created by the service.
- Done-state options depend on an issue in the team being loaded in the inbox first; an empty Done select is correct for a team with no loaded issue.
- Start is disabled when `issue.mapped` is false even when Linear itself is healthy; do not treat a disabled button as a broken inbox.
- Never start a session on an issue or a team whose repository is not a `fixture git-repo` copy: the session can push a branch and open a real PR.
- Linear error texts are service-sent and not translated; assert on test ids and the `role` attributes, not wording, except the key-name sentence which names env vars.
